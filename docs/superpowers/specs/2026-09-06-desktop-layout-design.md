# DevNest PC 端布局与界面规范优化设计

## 背景

DevNest 已具备完整的工作台、项目、知识库、系统公告、意见交流、系统工具、人员管理和个人资料页面。现有界面已经形成以蓝色为品牌色、浅色与深色双主题、Lucide 线性图标为主的视觉语言，但布局规则仍主要分散在各页面中。

在 1440px 以上桌面视口中，普通页面会随可用宽度无限拉伸。统计卡片、表格列和表单因此过宽；部分页面又通过固定视口高度制造内部滚动，数据较少时留下较大的空白区域。字体、图标容器、圆角、阴影和间距虽然大多接近，但仍存在零散的 9px、10px 字号、原始颜色和页面专用尺寸，使跨页面的层级感不够稳定。

本次优化只面向 PC Web，不新增或重做 H5、手机和平板布局。已有移动端媒体查询保留，以避免破坏现有代码，但不作为验收目标。

## 设计目标

1. 在 1280px、1440px、1920px 和更宽的桌面视口中保持稳定的内容密度与阅读宽度。
2. 让导航、页头、统计卡片、内容面板、列表和表单形成一致的视觉层级。
3. 减少数据较少时的大面积空白和没有必要的页面内嵌滚动。
4. 保留现有品牌、信息架构、业务操作、路由、API 和明暗主题行为。
5. 改善键盘焦点、图标语义、文本可读性和减少动画偏好下的体验。
6. 将公共规则放在负责它们的全局样式或共享组件中，页面只保留业务特有布局。

## 采用方案

采用“共享 PC 布局规则 + 重点页面定向收紧”的平衡方案。

不进行全量视觉重做，也不引入新的 UI 框架、图标库或网络字体。现有蓝色主题、系统字体、Lucide 图标、Pinia 状态、Vue Router 路由和各业务 Store 保持不变。

## 布局体系

### 内容宽度

全局建立三种桌面内容轨道：

- 标准内容：最大宽度 1600px，用于工作台、项目、系统公告、意见交流和人员管理。
- 聚焦内容：最大宽度 1280px，用于个人资料、改密和以表单为主的页面。
- 宽工作区：最大宽度 1840px 或使用完整可用宽度，用于知识库列表、Markdown 编辑器和系统工具。

`.page-content` 默认使用标准内容轨道并水平居中。需要聚焦或宽工作区的页面通过语义类选择对应轨道，不再在页面中反复声明 `max-width: none`。

页面左右留白使用统一桌面 gutter。在较窄桌面保持 24px，在宽屏提高至 32–40px。宽工作区仍保留最小安全内边距，避免内容贴边。

### 页面垂直节奏

建立 4px/8px 基础的间距层级，并重点统一以下关系：

- 页面顶部至页头：32px。
- 页头与首个模块：24px。
- 同级模块之间：16px 或 20px。
- 面板内边距：常规 20–24px，密集列表 12–16px。
- 标题、说明文字和操作区采用固定的 6px、8px、12px 间隔。

现有圆角继续使用 `--radius-sm`、`--radius-md`、`--radius-lg`。阴影只表达悬浮或浮层，不作为每张普通卡片的装饰。

## 应用外壳

左侧导航保持常驻并允许用户主动收缩。桌面展开宽度维持约 224px，收缩状态保持当前行为。顶部栏继续承载面包屑、搜索和全局操作。

顶部栏与页面内容使用相同的水平节奏。搜索框保留当前快捷键和结果弹层，结果列表继续支持键盘选择。

路由切换后，主内容区域应成为明确的焦点目标，方便键盘与屏幕阅读器用户定位新页面。所有仅含图标的按钮继续提供可访问名称；与可见文字重复的装饰性图标从辅助技术树中隐藏。

## 页面调整

### 工作台

- 四张概览卡继续保持同一行，但降低最小高度和内部留白。
- 使用现有语义颜色变量区分任务、项目、代码片段和文章，不保留页面内硬编码色值。
- 移除任务与项目面板基于 `52svh` 的固定高度，改为较紧凑的最小高度和内容驱动高度。
- 避免数据较少时出现大块空白；数据较多时优先使用页面滚动，只有明确需要的长列表才保留内部滚动。
- 最近知识区域与上方面板保持一致的卡片密度和标题层级。

### 项目

- 统一工具栏、筛选器、项目卡片和空状态的上下间距。
- 限制说明文字宽度，避免在超宽屏形成过长行。
- 状态、进度和操作按钮保持同一对齐基线。

### 知识库与 Markdown 编辑器

- 浏览和列表模式使用宽内容轨道，避免表格列拥挤。
- 阅读模式继续使用约 960px 的正文宽度。
- 编辑模式继续占用完整可用工作区，不受标准页面最大宽度限制。
- 不改变草稿、并发版本、图片上传、分享和缓存行为。
- 本轮只整理与布局一致性直接相关的样式，不拆分 `KnowledgeView.vue` 或 `MarkdownWorkspace.vue` 的业务逻辑。

### 系统公告

- 发布区继续突出 Markdown 编辑与实时预览，标题和说明占用更少垂直空间。
- 编辑器高度使用桌面友好的区间，左右两栏宽度稳定。
- 公告归档列表使用与其他数据列表一致的表头、行高和操作位置。

### 意见交流

- 保持消息流、回复折叠、滚动加载和图片异步读取行为。
- 收紧发布区与消息列表的间距，并限制正文阅读宽度。
- 头像、作者、时间、正文、附件和回复操作建立明确的纵向顺序。

### 系统工具

- 保留全高工作区和三个工具页签，不套用标准内容最大宽度。
- 统一页签、输入区、结果区和卡片的内边距。
- 保持用户自行控制侧边栏收缩，不增加自动收缩行为。

### 人员管理

- 统计、邀请、人员目录和操作记录使用相同的标准内容轨道。
- 人员表头与数据列继续共用网格定义，状态列保持对齐。
- 管理员操作记录的图标使用固定框体并从几何中心定位，操作文字、结果和时间保持清晰分列。
- 不改变管理员权限、模拟成员、审计内容或危险操作确认流程。

### 个人资料

- 使用聚焦内容轨道，避免资料表单在宽屏上过度分散。
- 头像、基础信息、安全设置和账号摘要保持清晰分组。
- 不改变头像、昵称、性别或密码的后端校验规则。

## 字体、颜色与图标

- 正文和操作文字继续使用系统字体，避免新增外部字体加载。
- 常规正文保持 14–16px；主要元数据至少 12px。只有极短的非关键徽标允许 10–11px。
- 将工作台等页面的原始紫色、橙色和绿色值替换为 `--violet`、`--warning`、`--success` 等语义变量，确保明暗主题一致。
- 图标继续统一使用 Lucide 线性风格。同一层级使用一致尺寸；图标框使用固定尺寸、显式水平与垂直居中。
- 功能状态不得只依赖颜色，同时保留图标或文字提示。

## 动效与交互

- 保留 140–220ms 的轻量状态变化，避免新增滚动演出或复杂动画。
- 悬停和按下反馈只改变颜色、边框、阴影或 `transform`，不改变布局尺寸。
- 继续支持 `prefers-reduced-motion: reduce`，减少动画时直接呈现最终状态。
- 可点击卡片、页签、筛选器和图标按钮必须拥有可见的 `:focus-visible` 状态。

## 代码规范调整

- 公共宽度、间距、字体和表面层级进入 `src/style.css` 的语义变量与共享类。
- `PageHeader.vue` 负责统一页面标题、说明和操作区布局。
- 页面 scoped CSS 只保留该页面独有的网格和状态，不复制公共面板规则。
- 不因文件较大而进行无关拆分；大型知识库组件的模块化作为独立后续任务处理。
- 不新增无实际使用者的抽象、配置项或依赖。
- 保留路由懒加载、Store 隔离、管理员工作区头和现有安全边界。

## 数据与错误处理

本次不修改 API、数据库、Store 数据结构或后端服务。加载、空状态、错误提示、确认弹窗和通知沿用当前实现。布局修改不得隐藏错误恢复入口，也不得让加载内容引发布局明显跳动。

## 验收标准

1. 在 1280px、1440px 和 1920px 桌面宽度下，普通页面内容不会无限拉伸，左右留白自然。
2. 工作台概览和主面板不再因固定视口高度产生明显空白。
3. 知识库编辑与系统工具仍能使用完整工作区。
4. 页面标题、卡片、列表、按钮和图标的尺寸与间距跨页面一致。
5. 浅色与深色主题均无明显对比度、边框或状态色回退。
6. 键盘焦点可见，图标按钮有名称，减少动画设置有效。
7. 业务路由、数据读写、管理员功能、公告、消息、分享和图片行为不变。

## 验证计划

- 运行 `npm test`，确认现有前端逻辑测试全部通过。
- 运行 `npm run build`，完成 Vue/TypeScript 类型检查和生产构建。
- 运行 `npm run test:ui:build`，验证隔离 UI 夹具可以构建。
- 按 `first-project-web/tests/ui/README.md` 使用隔离夹具检查 1280px、1440px、1920px 的工作台、人员管理、知识库、公告、消息、工具和资料页面。
- 分别检查浅色、深色和减少动画状态。

## 风险与回退

主要风险是全局内容宽度和共享间距影响特殊编辑页面。通过明确的标准、聚焦和宽工作区三种轨道隔离该风险，并对知识库编辑器和系统工具进行单独验证。

改动以 CSS 变量、共享类和页面 scoped CSS 为主，不涉及数据迁移。若某一页面发生回归，可以回退该页面的轨道选择或局部覆盖，而不影响业务数据。
